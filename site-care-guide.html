حماية الموقع وقاعدة البيانات

خطوات بسيطة تساعدك على المحافظة على موقع ملف الأداء الوظيفي، الشواهد المرفوعة، وحساب Supabase بأمان واستقرار.

3أنظمة يجب متابعتها
15 دمراجعة شهرية مقترحة
0مفاتيح سرية تُنشر
قاعدة ذهبية: الموقع العام للعرض فقط، أما الرفع والإدارة فيتمّان من مركز الملفات. لا تضع أبدًا Secret Key (المفتاح السري) داخل ملفات الموقع أو ترسلْه لأي شخص.
1

افتح الموقع واختبر الروابط Live Site

كل شهر⌄

افتح رابط الموقع من هاتف وكمبيوتر، ثم جرّب الصفحة الرئيسية، الأقسام، معرض التجارب، والبريد الإلكتروني.

إذا فتح الموقع وظهرت البطاقات والمختبرات، فواجهة العرض تعمل بشكل طبيعي.
2

راجع ملفاتك في مركز الملفات File Center

كل شهر⌄

اضغط زر «الملفات» في أعلى الموقع، سجّل الدخول بالرمز، وتأكد من ظهور آخر شاهد مرفوع داخل القسم والفرع الصحيح.

  • تأكد من أن نوع الملف صحيح: صورة أو PDF أو فيديو.
  • لا ترفع ملفات أكبر من الحد المناسب، خصوصًا الفيديو.
  • افتح رابط شاهد واحد للتأكد من إمكانية المشاهدة.
3

راقب مساحة التخزين Storage

عند الرفع⌄

احذف النسخ المكررة والملفات غير الضرورية من مركز الملفات لتقليل استهلاك التخزين والحفاظ على سرعة التحميل.

الأفضل تسمية الملف قبل رفعه على جهازك باسم واضح مثل: lesson-chemistry-2026.pdf.
1

افهم سبب التوقف Project Pausing

بعد قلة الاستخدام⌄

في الخطة المجانية، قد يوقف Supabase المشروع عندما يكون نشاط قاعدة البيانات منخفضًا خلال نحو 7 أيام. قد تصل رسالة تحذير قبل الإيقاف تقريبًا بأسبوع، ولا يعني ذلك حذف البيانات.

المهم: GitHub Pages يستضيف ملفات الموقع الثابتة، بينما Supabase هو الجزء الذي يحتاج متابعة النشاط والنسخ الاحتياطي.
2

نفّذ مراجعة أسبوعية حقيقية Weekly Maintenance

كل 7 أيام عند الإمكان⌄

افتح Supabase Dashboard (لوحة تحكم Supabase) وتحقق من حالة المشروع، ثم افتح مركز الملفات من الموقع وسجّل دخول الإدارة عند الحاجة.

  • Check project status — تحقق من حالة المشروع.
  • Review Storage — راجع الملفات ومساحة التخزين.
  • Test one read — افتح شاهدًا واحدًا للتأكد من القراءة.
لا تعتمد على إنشاء زيارات وهمية أو طلبات آلية بلا حاجة. استخدم نشاطًا إداريًا حقيقيًا، واحفظ نسخة احتياطية قبل فترات التوقف الطويلة.
3

إذا وصل تحذير الإيقاف Pause Warning

تصرف سريع⌄
  1. Open Dashboard — افتح لوحة Supabase.
  2. Open the project — اختر مشروع الموقع.
  3. Generate legitimate activity — نفّذ قراءة أو رفعًا إداريًا حقيقيًا عند الحاجة.
  4. Save a backup — احفظ نسخة من قاعدة البيانات والملفات.
4

إذا أصبح المشروع متوقفًا Resume Project

استعادة الخدمة⌄

من لوحة التحكم اختر المشروع المتوقف، ثم اضغط Resume project (استئناف المشروع). توضح وثائق Supabase أن الاستعادة من المنصة متاحة عادةً لمدة تصل إلى سنة من تاريخ الإيقاف، لذلك لا تؤجل النسخ الاحتياطي.

بعد الاستئناف، اختبر تسجيل الدخول، رفع شاهد تجريبي صغير، وفتح شاهد قديم قبل اعتماد الموقع.
5

إذا كان الاستمرار مهمًا جدًا Paid Plan

خيار اختياري⌄

المشاريع المدفوعة لا تتعرض للإيقاف التلقائي بسبب عدم النشاط وفق توثيق Supabase. لا تحتاج إلى الترقية لموقع صغير، لكنها تصبح خيارًا عندما تكون الاستمرارية دون متابعة يدوية أولوية.

1

نسخة ملفات الشواهد Storage Backup

شهريًا⌄

نزّل الملفات الفعلية من مركز الملفات واحفظها في مجلد منظم. نسخة قاعدة البيانات وحدها لا تعيد ملفات Storage المحذوفة.

  • 2026 / Section / Branch — السنة ثم القسم ثم الفرع.
  • احتفظ بنسختين: جهازك وقرص خارجي أو مساحة سحابية موثوقة.
  • افتح ملفين أو ثلاثة بعد التنزيل للتأكد من سلامة النسخة.
2

تصدير قاعدة البيانات Database Export

Supabase CLI⌄

من لوحة Supabase افتح Connect (اتصال)، وخذ Connection String (سلسلة الاتصال). استبدل كلمة المرور في جهازك فقط، ولا تحفظها في GitHub أو داخل الموقع.

Install CLI — ثبّت أداة Supabase CLI، ثم نفّذ الأوامر التالية بعد وضع سلسلة الاتصال بين علامتي اقتباس:

supabase db dump --db-url "[CONNECTION_STRING]" -f roles.sql --role-only
supabase db dump --db-url "[CONNECTION_STRING]" -f schema.sql
supabase db dump --db-url "[CONNECTION_STRING]" -f data.sql --use-copy --data-only -x "storage.buckets_vectors" -x "storage.vector_indexes"
الناتج: ملفات roles.sql وschema.sql وdata.sql. احفظها في مجلد احتياطي مشفر أو محمي بكلمة مرور.
3

احفظ إعدادات المشروع Project Configuration

مع كل تغيير كبير⌄

دوّن اسم المشروع، Project Reference (معرّف المشروع)، أسماء الجداول، واسم bucket التخزين. لا تسجل كلمات المرور أو المفاتيح السرية في هذا الملف.

4

الاستعادة الآمنة Restore

لا تجربها على الإنتاج أولًا⌄

أنشئ مشروعًا جديدًا للاختبار، ثم خذ سلسلة الاتصال الجديدة ونفّذ الاستعادة من جهازك. لا تنفذ أوامر الاستعادة على المشروع الأصلي قبل وجود نسخة ثانية.

psql --single-transaction --variable ON_ERROR_STOP=1 \
  --file roles.sql --file schema.sql \
  --command 'SET session_replication_role = replica' \
  --file data.sql --dbname "[NEW_CONNECTION_STRING]"

Verify Restore — تحقق من الجداول، ثم اختبر تسجيل الدخول ورفع شاهد وفتح ملف Storage.

الاستعادة قد تجعل المشروع غير متاح مؤقتًا، وقد تفقد التعديلات التي حدثت بعد تاريخ النسخة. خطط للوقت وخذ تأكيدًا قبل أي استعادة إنتاجية.
5

اختبار النسخة Restore Test

بعد كل نسخة مهمة⌄

افتح نسخة من جدول site_files، وتأكد من أن الروابط والمسارات مفهومة، ثم افتح ملفات الصور وPDF والفيديو. النسخة التي لم تختبرها ليست جاهزة للطوارئ.

1

استخدم رمز الإدارة بحذر Admin Code

دائمًا⌄

لا تكتب رمز الإدارة في الموقع العام أو في وصف الملف أو في رسالة جماعية. شاركه فقط مع الشخص المسؤول عند الحاجة.

تنبيه: المفتاح السري Secret / Service Role Key مختلف عن رمز الدخول، ولا يجوز وضعه في HTML أو JavaScript أو GitHub.
2

احمِ حساب Supabase Account Security

مرة واحدة⌄

فعّل التحقق بخطوتين 2FA إذا كان متاحًا، واستخدم كلمة مرور مختلفة وقوية، وراجع الأجهزة أو الجلسات المسجلة.

3

راجع صلاحيات التخزين Storage Policies

عند التطوير⌄

المشاهدة العامة يمكن أن تكون عبر الروابط المنشورة، لكن الرفع والحذف يجب أن يبقيا محصورين في المسؤول. لا تغيّر السياسات دون نسخة احتياطية.

1

الملف لا يظهر في الفرع

⌄
  1. انتظر قليلًا ثم حدّث الصفحة.
  2. تأكد من اختيار القسم والفرع الصحيحين عند الرفع.
  3. افتح مركز الملفات وابحث باسم الملف.
  4. لا تعِد رفع الملف مرات كثيرة قبل معرفة سبب المشكلة.
2

الموقع لا يفتح أو لم يظهر تعديل

⌄

جرّب نافذة خاصة أو تحديثًا قويًا، ثم انتظر انتشار النشر Deployment. إذا استمرت المشكلة، افحص حالة GitHub Pages بدل تعديل قاعدة البيانات.

3

فقدت الوصول أو شككت بتسريب الرمز

⌄

أوقف مشاركة الرمز، غيّره من إعدادات النظام إن أمكن، وراجع سجل الملفات. لا تحذف السجلات أو الملفات قبل حفظ نسخة احتياطية.

عند الاشتباه بتسريب مفتاح سري، يجب إلغاؤه وإنشاء مفتاح جديد فورًا من لوحة Supabase.

قائمة المتابعة الشخصية

ضع علامة بعد تنفيذ الخطوة. تُحفظ العلامات على جهازك فقط عبر Local Storage (التخزين المحلي)، ولا تُرسل إلى الموقع.
